# 运行问题检查与优化记录

检查日期：2026-10-30。修改基于 `2442e7b`，仅针对可以从代码和回归测试确认的问题；未添加项目依赖。

## 已修复的问题

| 问题与触发条件 | 修改后的行为 |
| --- | --- |
| 本地凭据文件缺少 Git 排除规则 | 忽略 `.env`、本地配置、`auths/` 和常见私钥文件，保留示例配置。文档示例的账号/任务标识改为明显虚构数据。 |
| 管理密钥通过 `?key=` 进入服务器访问日志 | 改为 `#key=`，读取后清除 fragment；保留手动输入和同源面板导入。原有 XOR 混淆存储保持兼容，明确它不提供加密保密性。 |
| 本机登录页面生成了 state，却没有验证；过期后仍可能返回成功凭据 | 首页校验 state，API 校验 `X-Login-State`；先检查过期再返回登录状态，关闭时清理内存凭据和会话。 |
| 登录页浏览器扫描返回的数据不含 token，前端却尝试提交这些字段 | token 保存在该登录会话的服务端，页面只提交所选候选索引，导入不再依赖向页面返回完整 token。 |
| 设置 `proxy_url` 后每个请求新建 HTTP Transport | 相同代理复用连接池；切换代理关闭旧池空闲连接；请求超时统一生效。 |
| 宿主 HTTP 超时、回调错误或 HTML 502/504 会重发 POST | 仅在宿主桥不存在，或明确的 HTML 405/501 拒绝时直连回退；避免已到达上游的生成/刷新请求重复执行。已取消的请求不再发起宿主回调。 |
| 参考图上传传入空客户端，且 `n=4` 会重复准备/上传四次 | 使用当前认证客户端上传一次，四个生成请求共享上传后的文件 key；准备阶段纳入并发限制并传递上下文。 |
| 图像轮询每轮同时调用两个端点；401/429 被吞掉直到任务超时 | 主端点已返回所需任务时跳过补充查询；4xx 及时返回，临时失败仍按现有轮询间隔重试。 |
| 任务超时只在 HTTP 返回后检查；取消期间可能留下永久 processing 行 | 每个任务使用实际 deadline，覆盖提交、轮询、签名；所有提交后的失败/取消路径更新终态并释放名额。多结果请求分别计算任务期限。 |
| 并发名额按配置数值创建多个独立池，热更新后叠加；面板满载时持续创建等待 goroutine | 所有配置共享活动任务数；降低上限等待原任务退出，面板满载直接返回 429。 |
| 冷缓存并发重复拉取，上游失败时每次模型请求都再次拉取，配置更新可能被旧请求覆盖 | 原子检查缓存和请求合并，失败短缓存 30 秒；失效版本阻止旧结果发布。删除模型发现中不影响返回结果的额外 profile 请求。 |
| 离线静态模型无法被 auto 选中，且静态模型绕过 include/exclude | auto 使用合并后的目录，静态项也遵守模型过滤。 |
| 同一次流式响应的每个 chunk 生成不同 ID/时间；输出失败后仍继续生成 | 分块共享 completion ID 和创建时间；进度输出失败取消后续工作。 |
| 诊断虽然脱敏 URL，但 `url.Error` 又带回完整签名查询参数 | 诊断只记录底层错误，避免从错误文本泄露签名 URL。 |
| 后台巡检停止时不取消正在执行的网络等待，生命周期字段缺少同步 | 用互斥锁管理启停，取消巡检上下文并等待该巡检退出；卸载前关闭本机登录会话。 |

## 可验证的性能变化

- 连续三次直连请求的测试只创建一条 TCP 连接，验证了显式 `direct://` 下的连接池复用。
- 一次 `n=4` 的带参考图请求只获取一次 STS、上传一次参考图，避免四次重复上传。
- 图像主查询返回任务时，每轮查询由两个请求降为一个。
- 20 个并发调用遇到模型目录故障时，只发出一次上游请求；短缓存期间不会连续重试。

这些是本地模拟上游的请求数和连接数验证，不是 Miora 生产环境吞吐量基准。

## 验证

环境：Windows/amd64，Go 1.27.2，LLVM-MinGW 20261020；项目的最低 Go 版本和依赖清单未变。

- 完整功能测试与 `go test -race ./... -count=1 -timeout=60s`。
- `go vet ./...`、`gofmt -l .`、`git diff --check`。
- `go build -trimpath -buildmode=c-shared -ldflags "-s -w"` 构建 Windows DLL，并检查 `cliproxy_plugin_init`、`cliproxyPluginCall`、`cliproxyPluginFree`、`cliproxyPluginShutdown` 四个导出。
- Gitleaks 对修改后目录及提交补丁检查，扫描结果另存于审查工作区，不随源码打包。

未使用真实账户调用 Miora、浏览器数据或付费生成任务。宿主 ABI 没有单独取消 HTTP 回调的接口：本地停止等待不代表已经发出的上游请求或平台任务被撤销；因此修复重点是避免不确定结果的 POST 自动重放。
