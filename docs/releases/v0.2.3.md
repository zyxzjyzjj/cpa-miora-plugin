# v0.2.3

修掉"接入后没有任何反应"：流式请求现在**立刻**回应，不再等整轮跑完。

## 根因

CPA 的插件流是**异步契约**：`pluginhost/rpc_client_stream.go` 里 `executor.execute_stream`
返回后宿主才开始 drain chunk（源码注释写着 "Async streaming plugins can return before they
finish emitting chunks"）。插件之前把整轮 agent 会话跑完才返回，于是：

- 客户端从发出请求到收首个字节，要等整轮（冷启动 1–3 分钟）；
- 期间 bridge 只缓冲 16 个 chunk，再多就阻塞在 emit 上；
- 超时后客户端只看到 499 / 空响应。

## 修复

- **先返回、后推送**：`executorAgentStream` 立刻回 ack，agent 回合放到后台 goroutine，
  用独立 context（`agent_timeout_seconds`）跑，结束后 `host.stream.emit` 收尾。
- **进度可见**：首个 chunk 立刻发 `Miora Agent 已接单，正在准备沙箱…`，
  沙箱启动期间每 20s 发一次心跳。实测首字节 **7ms**（此前 60s 无输出）。
- **运行时持久化**：项目/运行时/会话写入
  `%LOCALAPPDATA%\cpa-miora-plugin\agent-state.json`，重启后直接复用，不再每次重新申请项目。
- **申请走直连**：项目/运行时/审批模式这类小请求绕过宿主 HTTP 桥（桥偶尔挂住会吃掉整个超时），
  统一 25s 超时直连 Miora。
- **传输优先 IPv4**：本机 IPv6 不通，Go 默认先试 v6，导致请求一直挂到 deadline
  （`wsarecv: failed to respond`），而 curl 走 v4 正常。现在自定义 Dialer 先 `tcp4`。
- **超时更合理**：单轮 `agent_timeout_seconds` 默认 420s；`session/new` 每次 120s、最多 3 次，
  间隔 15s。

## 实测

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 首个字节 | 60s+（或永不） | 7ms |
| 客户端感知 | 空白，最终 499 | 立即出现"已接单…" + 心跳 |
| 重启后 | 重新申请项目/沙箱 | 复用 `agent-state.json` 里的运行时 |
