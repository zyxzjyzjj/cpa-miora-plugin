# v0.2.5

修复生成台**视频 / 3D 看起来"没用、发不出去"**。

## 三个真因

1. **进度永远 0%**：`/api/ai/media-generate/progress` 里的 `createdAt` 是**数字**（`1793376268877`），
   而 `taskState.CreatedAt` 是 `string` → 整批 JSON 解析失败 → 轮询每次都是"任务查询未返回结果"，
   面板永远停在 `submitted`。
2. **提交错误被吞**：`/generate` 先返回 200，真正的上游拒绝发生在后台 goroutine 里，只写了事件日志
   （面板不显示），所以点"生成"像什么都没发生。
3. **免费档 3D 并发上限**：上游 `{"code":18001,"message":"Concurrent task limit reached.","data":{"scene":"3d","running":1,"limit":1}}`。
   队列里已经有一个 3D 任务在跑时，新的 3D 提交必然 429。

## 修复

- `taskState.CreatedAt/UpdatedAt` 换成能同时接受字符串和数字的 `flexString`，并加回归测试
  `TestTaskStateAcceptsNumericTimestamps`。
- **提交同步化**：`/generate` 现在同步调用 `submitGeneration()`，几毫秒内返回真实结果：
  成功带 `task_id`，失败返回上游状态码和可读原因（3D 限流给出中文提示）。
- **提交即入列**：提交成功立刻写 `submitted` 行，失败写 `submit_failed` 行并带错误，面板一眼能看到。
- **轮询失败可见**：连续失败会写 warn 日志（`task poll failed error=...`），不再静默。
- 默认 `use_host_http: false`（宿主 HTTP 桥在本机会挂住，直连实测 0.2–0.6s）。

## 实测

| 场景 | 结果 |
| --- | --- |
| 视频（minimax-h3-max，5s，16:9） | 8s 10% → 16s 50% → 32s 100% → 40s `completed`，产出 mp4 签名链接 |
| 3D（hunyuan-3d-pro-3.1） | 提交返回 task_id；同时再发一个 → 立刻 429 + 中文提示 + `submit_failed` 行 |
| 3D 长任务 | 上游 50% 处理中（单任务可跑数分钟），期间新 3D 提交被限流，属上游免费档规则 |
