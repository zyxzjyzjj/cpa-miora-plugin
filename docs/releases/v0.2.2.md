# v0.2.2

工具产物回传：Agent 出图后，回复里终于带图片链接。

## 修复

- **接上 artifact 通知**。设计工具的结果不走 `tool_call_update`，而是独立的
  `_codebuddy.ai/artifact` 通知（`params.artifact.uri` + `type`）。此前插件只读
  `session/update`，所以回复只有"已生成"这三个字，图片链接被丢掉。
  现在 artifact 与 `tool_call_update.rawOutput` 两条来源都会提取，
  以 Markdown 图片追加到回复末尾。
- 单测覆盖：假 ACP 服务端发出真实形状的 artifact 通知，断言链接被收集。

## 关于"客户端工具"（终端 / 文件 / 审批弹窗）

- **审批**：已经自动化。项目级 `tool-confirmation/mode=auto` + 会话 `bypassPermissions`，
  实测同一句"生成戴墨镜的柴犬"从卡 4 分钟变成 20–25s。
- **终端 / 文件**：ACP 协议里有 `clientCapabilities.fs{readTextFile,writeTextFile}` 与
  `terminal` 两个开关，但 Miora 自己的 web 客户端把它们声明为 **false**
  （bundle 里 `um={fs:{readTextFile:!1,writeTextFile:!1}…}`），Agent 也是设计型 Agent
  （实测拒绝执行 shell / 代码）。也就是说上游不会发起这类请求，插件声明了也没有触发路径。
- 传输层也要改：客户端工具要求**双向** ACP（服务端发请求、客户端回响应），
  现在的 `/bootstrap` 是一次 POST + SSE 单向流。官方客户端同样基于 fetch+SSE，
  说明上游目前没有为这条路做准备。
