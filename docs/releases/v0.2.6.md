# v0.2.6

修复 `pi-ai detected context overflow for model "deepseek-v4.1-flash"`，并给 Agent 对话提速。

## 根因

Miora 不公开 Agent 模型上下文窗口，插件此前按 **200000** 声明。但 Agent 自带很大的系统提示词，
再加项目记忆累积，服务端实测一轮请求就是：

```json
"usage":{"prompt_tokens":245284,"completion_tokens":938}
```

24.5 万 > 声明的 20 万 → 客户端/网关判定 `context overflow` 并拒绝这次回复（上游其实是成功的）。

## 修复与提速

- **对外声明 1,000,000 上下文**（`agent_context_length`），与实际能力对齐，不再误判溢出。
- **项目记忆预算**（`agent_max_prompt_tokens`，默认 150000）：Miora 把每一轮都留在项目里，
  prompt 会从 4.9 万一路涨到 24 万以上，越聊越慢。现在一轮超过预算后，
  插件在回复交付之后把这个账号切到新项目（记忆清零），下一轮回到 ~4.9 万的基线。
- 两项都可配置，面板设置页同步暴露。

## 实测（生产服务器，Miora 侧）

| 项 | 数值 |
| --- | --- |
| 修复前 | `prompt_tokens=245284`，客户端报 context overflow |
| 单轮耗时（累积记忆） | 3.4s（还在涨） |
| 切新项目后 | 回到 ~49k prompt，热启动下 4s 级 |

## 部署提示

在 CPA 里更新到 0.2.6 并重启，或按 README 的手动方式替换 `plugins/<os>/<arch>/miora-provider-v0.2.6.so`。
