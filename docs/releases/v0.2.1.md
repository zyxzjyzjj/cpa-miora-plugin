# v0.2.1

Agent 工具调用链路的可用性修复。

## 修复

- **项目级工具审批改为 auto**：申请运行时后自动调用
  `POST /api/ai/tool-confirmation/mode {projectId, mode:"auto"}`。
  此前设计类工具（`mcp__image_tools__image_gen`）每次调用都停在 `pending` 等人工确认，
  实测卡满上游超时（4 分钟）才放弃；现在同一条提示词 **20–25s** 完成并出图。
- **会话冷启动重试**：沙箱刚创建时管理器会回 `SingleSessionId: no session available after 40s`，
  现在按 20s 间隔重试 4 次，而不是直接把 502 抛给客户端。
- **显式超时**：`session/new` 240s、单轮 prompt 由 `agent_timeout_seconds` 控制、
  `session/close` 15s，避免流式通道无限挂起。
- **复用单会话**：沙箱是单会话模型（`SingleSessionId`），运行时缓存 `sessionId` 后复用，
  会话被回收时会清空并重开一次。
- **回传工具产物**：工具 `completed` 帧里的 `access_url` / `file_key` 会被提取并以
  Markdown 图片追加到回复（单测用真实 payload 覆盖）。

## 实测（Windows + CPA v7.3.9）

| 场景 | 结果 |
| --- | --- |
| 纯文本对话 | 4s / 12s / 26s 不等，稳定 |
| 图像工具（`生成一张图：戴墨镜的柴犬`） | 21–25s，`tool_call` 触发，回复"已生成" |
| 隔离沙箱原始帧 | `tool_call x2`、`tool_call_update x87`、最终 `status=completed`，payload 含 `access_url` |

## 已知限制

- 该 Agent 是**设计类** Agent，明确拒绝执行 shell / 代码（"我这边不直接执行命令或代码"），
  所以"跑命令"这类工具本来就不存在；可用工具是图像 / 视频 / 3D / 文档 / 画布相关。
- 部分工具路径的 `completed` 帧不带 `rawOutput`，此时回复只有文本描述，
  图片落在 Miora 项目里（画布/产物），插件暂时无法从这里取回 URL。
